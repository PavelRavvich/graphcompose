## Why

AI agents write most of the code in this repo, not people. A framework built for that has to make two things true. A correct change should be cheap for an agent to make. A wrong change should be caught quickly, by `tsc`, by assembly or by a gate, and not show up as a silent failure in production.

This epic records a full architecture review (`.claude/skills/framework-review`) of commit `cc93d97`, with a concrete proposal for every finding.

- **Commit choice:** `cc93d97` is the last commit that builds. HEAD `6c3badc` fails at `flow-nodes.ts:186` (`quorumMax`). The working tree fails at `assemble.ts:187` and `saga.ts:2`.
- **Stage:** early. The API is still moving and there is one example. Weights are ×2 on axes 1, 2, 3, 14, 17 and ×0.5 on 9, 15.
- **Weighted score: 2.0 / 5.**
- **Strong core:** `deps` are checked against the constructor at compile time with no reflect-metadata, the graph rules are strong, and the MCP boundary is typed.
- **Weak surroundings:**
  - Many paths around that core pass `tsc`, assembly and tests and then silently do nothing.
  - All three feedback channels an agent relies on are broken right now: the gate, the docs and the generators.

**Method:**
- 4 static reviewers: types & API, agent runtime, quality & ops, CLI.
- 3 empirical probes:
  - **P1:** a fresh agent implements a feature.
  - **P2:** 35 misconfiguration variants.
  - **P4/P5:** the CLI contract and the generators.
- An independent verifier then checked 20 key claims: 16 were confirmed, 3 were confirmed but sharpened, and none were rejected.

## Blockers, grouped by root cause

### B1. The agent's feedback loop is broken (axes 14, 5). Fix first: nothing else can be verified without it.

**Evidence:**
- HEAD does not build. The last pipeline commit was pushed with a red `tsc`.
- `make check` is red:
  - eslint: 456 errors in framework `src`
  - prettier: 26 files
  - framework `tsc`: 20 errors, 18 of them in tests
  - example `tsc`: 13 errors
  - example lint: 27 errors
- An agent running "Gate: `make check`" from `implement/SKILL.md` sees red before it touches anything, so it cannot tell its own errors from existing ones. In P2, lint caught **0 of 35** misconfigurations.
- vitest does not typecheck. `tests/graph/fork-join/quorum.test.ts:42` passes a callback as `testWith`'s options, so the test body never runs. The test is "green" in 2 ms while the file has 18 `tsc` errors, and the feature it claims to cover is dead (see B2).

**Proposals:**
1. **One-time cleanup to green.** Fix the 20 + 13 `tsc` errors. Run `prettier --write`. For eslint, either fix the errors or freeze them with an `eslint-suppressions.json` baseline, so that only *new* violations fail.
2. **Typecheck tests on every run.** Add `typecheck: { enabled: true }` to the vitest config, or make the `test` script `tsc --noEmit -p . && vitest run`. Turn on `expect.requireAssertions: true` in the vitest config.
3. **CI on every PR** running `make check`, with branch protection on `dev`.
4. **Pipeline guard:** the `implement` skill must not push or commit while the gate is red. Add a pre-push hook that runs `npm run typecheck`.
5. **Gate diff mode:** `make check` prints "new errors vs baseline", so agents see only their own errors.

### B2. Extension points that pass `tsc`, assembly and tests but do nothing (axes 3, 4)

| What | Why it is dead | Evidence |
|---|---|---|
| Approval via `@Channel` | `approval.ts:63` checks `e.name === "NodeInterrupt"`, but LangGraph 1.4.18 throws `GraphInterrupt`. On top of that, `assemble.ts` never fills `bundle.channels`, so `dispatchChannel` would throw "Unknown channel" anyway | probe: `dispatched: []`. job-scout's `save_shortlist` has `channel: TerminalUserChannel` and never prints |
| Guardrails / PII policies | `app-deps.ts:217` calls `services.resolve(cls)`, which does not exist on `WorkflowServices`. The unit test passes a mock that has `resolve` | probe: `createApp` → `TypeError: services.resolve is not a function`. Agent- and tool-level policies crash on first call |
| `deps` on Guardrail / PiiPolicy / Channel / InboundAdapter | type-checked against the constructor but never injected (`container.ts:296-305` `depsOf` knows only tool/mcp-tool/injectable/rag) | read |
| Observers (`onWorkflowStart`, …) | `ObserverManager(lifecycle.created)` over a lazy container: an observer nobody injects is never created. Hooks are matched by method-name strings and typed `any` | probe: `observer calls: []`. The repo's own test works around this with `deps:[GlobalObserver]` on a tool |
| Quorum (`joinQuorum`) | nothing puts `quorumManager` into the run config (`run/paused.ts:8` sets only `thread_id`) | see B1 |
| `ExecutionOptions.onStream` | `create-app.ts:88` does not forward it to `runAgent` | read |
| `WorkflowActionContext.runId` | reads `configurable.runId`, which is never set, so it is always `""` | probe |

**Proposals:**
1. **One end-to-end test per extension point** through `testWith`, with no mocks of internals: a channel receives an approval request, a guardrail trips, an observer is called, quorum cancels the slower branch, `onStream` receives events, and `runId` is a non-empty UUID. These tests would have caught every row above.
2. **Channels:** use `isGraphInterrupt(e)` from `@langchain/langgraph`. Assemble `channels` / `channelAdapters` in `workflowOf`, and fail at assembly if a tool names a channel that is not registered.
3. **Guardrails / PII:** resolve through `containerFor(bundle, services)`, the same path tools use. Put every DI-capable kind into `depsOf` and into the `checkGraph` roots, using one `deps` metadata field for all kinds.
4. **Observers:** add explicit registration, created eagerly and typed by interfaces, instead of duck typing:
   ```ts
   @Workflow({ observers: [MetricsObserver] })
   @Injectable()
   class MetricsObserver implements OnWorkflowStart, OnToolEnd {
     onWorkflowStart(e: WorkflowStartEvent) { … }   // typed event, no `any`
   }
   ```
5. **One typed run context**, built once in `streamConfig`, to replace the scattered `configurable.runId` / `run_id` / `metadata` reads:
   ```ts
   interface RunContext { runId: string; threadId: string; metadata: Readonly<Record<string, string>>; quorum?: QuorumManager }
   const run = runContextOf(config); // single typed accessor
   ```
6. **Until an extension point works, stop exporting it** (or mark it `@experimental` in TSDoc and WORKFLOW.md). A dead public API is worse than a missing one, because agents trust it.

### B3. Silent holes in DI (axis 1)

| Agent mistake | Caught at | Evidence |
|---|---|---|
| `ENV` is `InjectionToken<any>`. Without `--env` the CLI injects `process.env`, and the base `environment.ts` is never loaded | **never**. This is a live bug in the example: `npm run chat` fetches `undefined/v1/boards/…`, every board fails, and the run "succeeds" with zero jobs. Tests hide it because they construct the service by hand | `runtime.ts:18`, `load-workflow.ts:51`, P2 #2d |
| `{provide: TOKEN, useValue: <anything>}` | runtime; the error is swallowed into `Tool error: …` | `injection.ts:27`, P2 #2e/2f |
| Class provider without `@Injectable` whose constructor takes args | runtime: `undefined` fields | `container.ts:4-14`, probe |
| Two tools with the same `name` | **never**: one agent's tool call runs another agent's handler | `parts.ts:26` (`new Map` by name), P2 #10a |

**Proposals:**
1. **Typed environment, loaded by default:**
   ```ts
   export const ENV = environmentToken<AppEnvironment>();          // InjectionToken<AppEnvironment>
   @Workflow({ environment: { default: () => import("./environments/environment.js"),
                              staging: () => import("./environments/environment.staging.js") } })
   ```
   Fail at assembly if anything depends on `ENV` and no environment resolves.
2. **Typed value providers.** Replace `{ provide, useValue: unknown }` with a helper that ties the value to the token:
   ```ts
   export function provide<T>(token: InjectionToken<T> | Class<T>, value: T): Provider;
   providers: [provide(JOB_SEARCH, searchConfig)]   // wrong shape → tsc error
   ```
   Optionally, a token can carry a DTO class for runtime validation at assembly.
3. **Reject undecorated class providers.** At assembly, if a class has no component metadata and `cls.length > 0`, raise `[di.undecorated-provider] SalaryTable takes 1 constructor argument but has no @Injectable({ deps })`.
4. **Unique tool names.** Add a rule `[tool.duplicate-name]` in `workflowOf` that covers local, MCP and RAG-generated tool names, per agent and across the workflow.

### B4. The docs describe a different framework (axes 14, 7)

**Evidence:**
- **CLAUDE.md**, the agent's primary context, documents a flow DSL that no longer exists:
  - documented: `from().to()`, `.choose()`, `route(X, "…")` and router `instructions`;
  - actual code: `.next()`, `.routes()`, `{prompt, target}` and `prompt`/`promptUrls`.
- **README** uses fields that don't exist (`instructions`, `promptVars`, `budget`, `routers`, `agents`) and imports from the root things the root does not export. Compiling the snippet gives TS2305 five times.
- **Three conflicting import rules**: CLAUDE.md allows 4 entries, eslint allows 6, and the example uses 11. The root does not export `Agent`, `Tool` or `Injectable`, so no agent can satisfy all three rules at once. The P1 agent, verbatim: *"Which import path is the sanctioned one when the lint rule bans `graphcompose/core` and `graphcompose/tool` but the root package doesn't export `Agent`, `Tool`, `Injectable` or `ToolHandler`."*
- **Other stale statements:**
  - LangSmith tracing (the code uses Langfuse);
  - `@WorkflowPause` and the `*Judge` classes (not exported);
  - `npm run test:routers` (no such script);
  - "No `any`" (there are 123).
- The only accurate DSL description is `DSL_PHASE_2_SPEC.md` at the root, and CLAUDE.md forbids keeping specs as files.

**Proposals:**
1. **Compiled doc snippets.** Every code block in README / CLAUDE.md / WORKFLOW.md either lives in `docs/snippets/*.ts`, compiled in CI and included by a marker, or references an example file by path (`see examples/job-scout/src/agents/scout.agent.ts`) instead of inlining code. A stale snippet then fails CI.
2. **One entry-point layout.** Either re-export every authoring decorator (`Agent`, `Workflow`, `Router`, `Tool`, `Injectable`, `ENV`, `ToolHandler`, `ToolContext`) from the root and keep subpaths for advanced use, or bless the subpaths. In both cases, **generate the eslint allow-list from `package.json#exports`**, so the docs, the lint rule and the example cannot diverge.
3. **Rewrite the Architecture section of CLAUDE.md** from the current code (`.next/.routes/.nextParallel/.join/.joinQuorum/.batchParallel`, `{prompt, target}`), then delete `DSL_PHASE_2_SPEC.md` and the `ticket-*.md` files from the root.
4. **Extend `check-old-names.sh`** with the retired DSL words (`.to(`, `.choose(`, `route(`, `instructions:`, `promptVars`).

### B5. The agent generator produces a dead prompt (axis 17)

**Evidence:**
- `templates/agent/agent.ts.tmpl` has no `promptUrls`, yet `gc g agent` and `gc create` write `<x>.prompt.md` next to it. An agent edits the prompt, and the model never sees it.
- The template also imports `../models.js`, which exists only in the `gc create` layout. In the example this gives +1 `tsc` error, and 5 of 8 test files fail to load.

**Proposals:**
1. Emit `promptUrls: ["./{{kebab}}.prompt.md"]` in the template.
2. At assembly, warn on any `*.prompt.md` next to a component that no component references.
3. Resolve the model constant from sibling agents in the target workflow (read the AST), instead of a hard-coded `../models.js`.
4. Add a CI job: for every generator, generate into a fresh `gc create` project **and** into `examples/job-scout`, then run `tsc` + lint + tests. Both must stay green.

## Major findings by axis (each with a proposal)

**Axis 1: Type safety**

- **`execute()` is not tied to the start's DTO.** `execute(start: Class, input: WorkflowStartText)`: adding a required field to the start DTO compiles everywhere and then fails with `DtoValidationError` on the first call (P2 #4). Passing an agent class as the start also compiles.
  - *Proposal:* `execute<S extends StartClass>(start: S, input: InputOf<S>)`, where `StartClass` is branded by `@WorkflowStart`.
- **Every list slot is typed `Class`.** This covers `tools`, `mcp`, `guardrails`, `rag.use` and the `flow` nodes. Putting a service into `tools` compiles and fails only at assembly (P2 X1).
  - *Proposal:* the decorators already return `C`, so brand it (`C & { readonly [ToolBrand]: true }`) and type the slots `ToolClass[]`, `McpServerClass[]`, `FlowNode = AgentClass | RouterClass | …`. The error moves from assembly to `tsc`.
- **`@WorkflowAction` has no `deps`.** Constructor parameters arrive as `undefined`.
  - *Proposal:* give it the same `deps` + `ResolvedAll<D>` contract as `@Tool`.
- **`deps` errors are TS1238 overload dumps.** They point at the decorator line and never mention `deps` (P2: 11 of 35 errors only "partly" fixable from the text).
  - *Proposal:* a branded error type, e.g. `DepsMismatch<"deps[1] is FtsOptions, constructor parameter 2 wants JobSearch">`, surfaced through a conditional parameter type.
- **Graph-rule messages use the internal name `choose(...)`.** The public API is `.routes(...)`.
  - *Proposal:* use the public names in rule texts, and add `file:line` of the offending `from(...)` call when it can be resolved.

**Axis 2: API fitness for an agent author**

- **Adding an agent takes 5 edits in 3 files.** The router's `routes` duplicate the flow's `.routes(...)`.
  - *Proposal:* make one of them the source of truth. For example, the flow derives the targets from `@Router({ routes })`, so `from(MainRouter).routes()` with no arguments, or the reverse.
- **False friends.**
  - The Angular-style `environments/environment.ts` is never loaded (see B3).
  - There are two different `ToolContext` types: `/core` holds the observer context, `/tool` holds the run context.
  - *Proposal:* rename the observer types (`ToolRunEvent`, `ModelCallEvent`), and either load `environment.ts` or remove the convention.

**Axis 3: Extensibility**

- **The only providers are a class or a value.** There is no `useClass` / `useFactory` / async factory, and no scope other than singleton. A per-tenant judge or a pooled DB client cannot go through DI.
  - *Proposal:*
    ```ts
    { provide: FIT_RATER, useClass: CheapJudge }
    { provide: DB, useFactory: async (env: AppEnvironment) => connect(env.dbUrl), deps: [ENV] }
    ```
    Type both through `ResolvedAll`. Add `scope: "run"` later if per-run instances are needed.

**Axis 4: Agent-specific abstractions**

- **Data between nodes is untyped.** `payload` is `Record<string, unknown>` with a shallow merge, and `IWorkflowAction<T = any>`. Renaming a key in the writer compiles, and the reader gets `undefined`.
  - *Proposal:* declare the payload schema on `@Workflow` (a DTO class), and type `from(A).next(B)` so that A's output must be assignable to B's input.
- **Agents in `batchParallel` never see their item.** `batchItem: undefined` in `runner.ts:45`.
  - *Proposal:* pass the item into the loop input and expose it as a prompt variable. Add a test.

**Axis 5: Testability**

- **`@WorkflowFinish({ output })` accepts a subclass, but the result is always `{text}`** (`result.ts:60`).
  - *Proposal:* type the option as exactly `typeof WorkflowFinishText` until structured finishes (#117) land, or reject subclasses at assembly.
- **`graphcompose/testing/setup` prints `HELLO FROM SETUP.TS`** in every consumer's test run.
  - *Proposal:* delete it, and ban `eslint-disable … no-console` in `src` via a lint rule.
- **Router slices call `condition({} as any)`.** A condition that reads state behaves differently in tests than in a real run.
  - *Proposal:* build the initial state from the state schema's defaults.

**Axis 6: Introspection & observability**

- **`describe --json` crashes, and tracing is hard-wired to Langfuse.**
  - *Proposal:* `describe --json` from the same model as the text output. Export `RunTracing` as a pluggable provider.

**Axis 7: Public surface & evolution**

- **14 overlapping entries with 327 names, and the same name means different things.** This applies to `ToolContext`, `ModelRequest` and `Router` (a type in `/core`, a decorator in `/graph`). Auto-import picks the wrong `ToolContext`, and the resulting TS1238 points at the decorator, not at the import.
  - *Proposal:* one name per meaning; merge `/router` into `/graph`; run `api-extractor` (or `tsd` over `dist`) in CI to track the public surface and catch accidental breaks.

**Axis 9: State evolution & long-running runs**

- **`promptVersion` / `configHash` hash prompt paths and functions' `.options`, not file contents.** Editing a `.prompt.md` does not change the version, so replay and eval mix old and new runs. Moving the checkout produces a false drift warning.
  - *Proposal:* hash the rendered template text plus the variables, without the absolute `source` path.
- **Resume rebuilds the current graph with no version check.** `PausedRunRepository` is synchronous, so it cannot be backed by a database.
  - *Proposal:* store `{version, configHash}` with each pause and refuse, or migrate, on mismatch. Make the repository interface async. Document that `MemorySaver` is dev-only.

**Axis 10: Security & isolation**

- **No tenant/thread binding.** A client-supplied `thread` passed to `app.execute` loads another tenant's history, and the daily cap is shared.
  - *Proposal:* bind a thread to an owner key carried in `RunContext`, reject on mismatch, and expose `account` on `ExecutionOptions`.
- **Tool and RAG output carries no trust marking.**
  - *Proposal (minor):* wrap untrusted tool output in a typed `Untrusted<string>` and render it with delimiters. Let write tools opt into a guard on untrusted input.

**Axis 11: Prompts & models as dependencies**

- **Variables in `promptUrls` files are checked only on the first model call.** The error names neither the file nor the known variables. Router prompts never go through `renderTemplate`, so `{{x}}` reaches the model literally. A fixture uses `prompt: "./support.prompt.md"`, which sends the path as text.
  - *Proposal:* at `workflowOf`, eagerly read and render every prompt, routers included. Error format: `[prompt.unknown-variable] agents/profiler.prompt.md:12 {{boardsCount}} — known: boards_count, region`. Add `gc check --prompts`. Warn when an inline `prompt` looks like a path.
- **`ModelCapabilities` has no tool-calling or context-window fields.**
  - *Proposal:* add them, and have `check --models` verify that agents with `tools` use a model that supports tools.

**Axis 12: LLM cross-cutting concerns**

- **Budgets can be overspent.** `spentToday` is read once per run with no reservation, so 10 concurrent runs can exceed the daily cap by up to 10×. Parallel branches each get the full remaining run budget.
  - *Proposal:* reserve and decrement in the ledger, and check the run budget against a counter shared across branches.
- **Error types are partly hidden.** `AgentFailedError`, `GuardFailedError` and `PaidStepError` are not exported. A cancelled run becomes a plain `Error`. Every tool exception, `TypeError` bugs included, becomes text for the model. `replay` silently drops failed runs.
  - *Proposal:* one exported error union with a stable `code`, a `CancelledError` class, and an option to rethrow programmer errors (`TypeError`, `ReferenceError`) instead of feeding them to the model. Record failed replays as score 0.
- **The fallback provider sends the primary's `model` id**, and cost accounting throws when the breaker opens.
  - *Proposal:* the fallback gets its own model mapping and prices, checked at assembly.

**Axis 13: Coupling to LangGraph**

- **LangGraph internals leak into public types.** `PromptInput = (state: FlowStateType) => …` exposes 23+ internal channels. The `.d.ts` files hold 843 references to `@langchain/langgraph`, so type errors in prompt code dump `BaseChannel<…OverwriteValue…>`.
  - *Proposal:* a narrow, framework-owned `PromptState` view. Declare `BaseChatModel` and the checkpointer as deliberate, documented public dependencies.

**Axis 14: Keeping agent-written code consistent**

- **The repo root is full of leftover scripts.** These are `fix_*.cjs`, `patch_*.cjs`, `remove_any.cjs`, `lint-results*.txt` (with local paths) and `scratch/`. Some regex-patch `build.ts` and add `any`, and agents grepping the repo copy that approach.
  - *Proposal:* delete them, add `/*.cjs`, `scratch/` and `*.log` to `.gitignore`, and have `check:rules` fail on new root-level scripts.

**Axis 15: Operational**

- **`dependencies` include CLI-only and unused packages.** These are `typescript`, `tsx`, `@inquirer/prompts`, the OTel stack and `langsmith`, some never imported. `knip.json` exists but is not wired in.
  - *Proposal:* split the CLI and scaffolder into `@graphcompose/cli`, or make them optional peers. Drop the unused packages and add `knip` to `check`.

**Axis 16: Evals integration**

- **Evals are CLI-only and real-model-only.** `src/eval/*` is not exported, the judge is always an LLM, golden sets have no expected answers, Terns carry no trace link, and there is no `--json`.
  - *Proposal:*
    - Export `evaluate` / `runProfile`.
    - Allow a scripted or fake judge and `expected:` in golden YAML, so evals can run in CI without a key.
    - Store `sessionUrl` on each Tern.
    - Add `--json` to `eval`.

**Axis 17: CLI**

- **The documented run command and `--help` crash.** `gc run --workflow <path> "task"` is documented in help, README and the example's `package.json`, and it crashes with `ERR_PARSE_ARGS_UNKNOWN_OPTION`. `<cmd> --help` crashes for 6 commands.
  - *Proposal:* one shared option schema per command, from which `parseArgs`, `--help` and `describe <command> --json` are all generated.
- **No machine-readable output and one exit code.** There is no `--json` and no `--dry-run`, every failure exits 1, and stack traces go to the user.
  - *Proposal:*
    - `--json` → `{ created, modified, warnings, nextSteps }`.
    - `--dry-run` → a unified diff.
    - Exit codes: 2 = usage, 3 = invalid project, 4 = conflict.
    - Stack traces only with `--debug`.
- **Generators hard-code the `gc create` layout.** `gc g router` in the example fails with `Not found: text.workflow-finish.ts`.
  - *Proposal:* resolve the start, the finish and the model constant from the target workflow's AST.
- **Re-running after a deleted file duplicates registrations**, caught only at assembly.
  - *Proposal:* check the class identifier, not the text, in every array and flow call, and exit 4 on conflict.
- **`gc create` without a TTY** prints inquirer ANSI to stdout and throws `ExitPromptError`.
  - *Proposal:* when `!stdin.isTTY`, never prompt. Report `missing --mcp (none|filesystem:<dir>|command:<cmd>:<tool>)` and exit 2.
- **Generated code needs follow-up fixes.** The generated test is outside the vitest `include`, the output fails Prettier, and `package.json` is fully re-serialised.
  - *Proposal:* place the test where the project's test config looks, run Prettier on touched files only, and edit `package.json` surgically.
- **The scaffold has no CLAUDE.md / AGENTS.md or ESLint config, and there is no graph check.** `gc check` validates only models.
  - *Proposal:*
    - The scaffold ships an agent guide and lint rules.
    - `gc check` runs every key-free validation (graph rules, prompts, MCP contract, models) and prints `file:line` + rule code + fix.
    - This is fast enough to wire as a post-edit hook.

## What is good (keep it)

- **`deps` checked at compile time.** `deps: [A, TOKEN]` + `ResolvedAll<D>` checks constructor count, order and type with no reflect-metadata. It caught 4 of 4 P2 variants at `tsc`.
- **Graph rules.** They report all violations at once with stable codes (`graph.dead-end`, `graph.cycle-without-router`, `router.routes-mismatch`). A missing provider error names both the consumer and the token.
- **Typed MCP boundary.** `McpServerClient<typeof tools>` checks tool name, argument and result types at compile time, and `McpContractError` checks against the live server. Tool input and output are validated by the same DTO the TS type comes from.
- **`testWith`.** Scripted models, `mockOf<T>`, MCP stubs, a blocked network, a clock and `restartApp`. 36 type-level tests use `@ts-expect-error`.
- **Secrets.** They reach providers only through `EnvironmentVariable.named(…, {secret:true})`, and MCP servers get variable names, never values.
- **Resilience and cost.** One retry/breaker layer per provider, paid failures still recorded, and `callId` as the tool idempotency key.
- **CLI basics.** Offline and fast, with AST-located edits that say "add X by hand" instead of guessing. `gc create --yes` produces a green project.
